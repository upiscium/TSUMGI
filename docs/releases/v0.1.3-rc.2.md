## Why a second RC is required

RC1 contained source-level opt-in audio Worker infrastructure but could
accept a generic `executor.factory` claiming an audio ServingContract
without an owned, supervised inference Runtime. A manifest/declared
capability is not evidence that a voice engine is actually running.

**PR #217 / #214 B5a:** With `audio.synthesize` or
`audio.transcribe`, the Worker now **rejects** `executor.factory`
before GPU preflight, Control registration, lease/claim and runtime side
effects. Audio must use an explicitly reviewed `runtime.manifest` and a
coherent `RuntimeHealthState.READY` before admitting its advertised
audio capability. A manifest alone cannot bypass provider-specific
readiness; unsupported VOICEVOX/Style-Bert/STT providers continue to
**fail closed**. Ordinary non-audio factories and Chat runtime paths
remain supported. The change adds targeted negative/positive tests;
it does **not** add a working voice runtime or enable audio by default.

  `store:false` compatibility.

  Serving gates, setup review and Worker media bridge. Unsupported
  models/runtimes are not auto-selected.

  (#215/#216/#181, plus #178/#179). Do not claim availability merely
  because the API or source adapter is packaged.

The release is a **patch-number increment by explicit maintainer
selection**, and includes opt-in feature groundwork in addition to
compatibility and safety changes. This is not presented as a
strictly fixes-only SemVer increment.

## Support and safety limits

- Technical Python package and service interfaces retain
  `astrumweaver` names (#120 deferred).
- No new PostgreSQL migrations and no implicit database schema or
  application state changes.
- Qwen3.8 and Bonsai runtimes stay separately pinned and opt-in;
  no model weights, NVIDIA drivers, PyPI upload, binary-cache
  publication or site fleet upgrade are bundled.
- Support is bounded to the reviewed trusted x86_64 Linux Nix
  and generic-systemd paths. No hostile same-UID isolation,
  universal GPU/voice quality, latency/uptime guarantees or
  unreviewed native runtime claims.
- RC2 `v0.1.3-rc.2` is **not stable GA**. A subsequent `v0.1.3`
  GA must preserve the RC2 functional source and migration bytes,
  only promote release metadata/docs, undergo full exact-source
  qualification, and be separately published.

## RC2 gates

1. Code change relative to published RC1 is *exactly* accepted B5a
   fail-closed managed-runtime enforcement and its source/tests/docs.
   No new B5b/B5c, audio deployment, or unrelated source changes.
2. Independent reviewer PASS; full Python regression, version
   alignment and negative security tests against exact candidate.
3. `nix flake check`, generated NixOS VM tests and
   `#control`, `#worker`, `#installer`, `#integration`
   builds; GitHub exact merged-head `unit` and `nix` Green.
4. Exact-tag wheel, sdist, Git archive deterministic double-build,
   migration/content safety, Nix output identity and manifest
   with checked SHA256SUMS. Publish with GitHub prerelease flag,
   leaving stable v0.1.2 unchanged.

No Control/Worker restart or GPU/model changes are implied by
release publication. Operator-site rollout/rollback remains a
separately approved activity.
