The scope since v0.1.1 is **exactly three merged functional changes**; previous opt-in Bonsai 2 PQ2_0 support remains intact.

1. **PR #158 — Upstream Qwen3.8 CUDA backend.** Adds the explicitly selected `#runtime-qwen38-llama-cpp` Nix package and pinned native CUDA/driver/PTX bridge. This does not replace the default `#runtime-llama-cpp` or separately pinned Bonsai backend. Real dual RTX3060 12GiB Qwen3.8 full-model SHA/GPU/Chat/Tool acceptance, Control→PostgreSQL→Worker→OpenCode 1.18.35 **6/6 Coding edits and 53/53 assertions**, and Qwen3.8→known-good-Qwen3.8→new Nix runtime recovery passed ([#157](https://github.com/upiscium/TSUMGI/issues/157)). Qualification is hardware/model-specific.
2. **PR #166 — Explicit guarded Worker Offline recovery.** Control-authored heartbeat-TTL expiry can trigger an authenticated re-registration with durable GPU ownership locks, active lease and Serving/runtime epoch checks; administrator Offline/Draining remains fail-closed. Successful Heartbeats alone cannot promote Offline. Production vega legacy-offline record required explicit fresh registration; real GPU-bound Job/rollback tested ([#162](https://github.com/upiscium/TSUMGI/issues/162)).
3. **PR #169 — OpenCode v2 compatibility.** Accept `store: false` and remove it before producing `chat-job-v1`, keep omission unchanged; reject `store: true` or malformed types. Production OpenCode v2.0.32 one-file synthetic edit and v1.18.35 backward test, and Bonsai Chat passed ([#167](https://github.com/upiscium/TSUMGI/issues/167)). **No Stored Completions persistence is added; #168 is Future Work.**

## Compatibility and safety boundaries

- Technical `astrumweaver` imports/CLI/systemd/env interfaces are retained (#120 deferred). PostgreSQL 17 UTF8 supported, migration files `000`–`005` unchanged from v0.1.1. No migration or live upgrade required for release publication.
- The operational acceptance above concerns previously installed main-line packages, not a v0.1.2-RC-specific full production fleet rollout. A GitHub source release alone updates no Control/Worker service, model, token, database, or GPU.
- If a future installed site update is authorized, deploy Control before updated Workers; use immutable Nix profiles, check idle leases/owner, and test rollback. Trusted/private Linux LXC boundaries remain; same-UID/native hardening #149 and draft PR #148 are deferred. Ops follow-up #160 remains open.
- No universal CUDA platform, model correctness, latency/uptime SLA, full 24-hour soak, fully hostile same-UID isolation, third-party attestation, PyPI publication or binary cache is claimed.
