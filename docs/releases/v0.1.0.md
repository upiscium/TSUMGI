# TSUMGI v0.1.0 — release notes

This document describes the **feature-frozen** v0.1.0 release line. Its presence in the source tree **does not establish publication**: verify the actual tag, immutable commit and released assets on [GitHub Releases](https://github.com/upiscium/TSUMGI/releases). The stable `v0.1.0` tag and artifacts require **separate maintainer approval** after exact-candidate qualification; neither a source PR nor a merge authorizes an installed-site cutover.

## Included capabilities

- PostgreSQL-backed Control with durable Job scheduling, Worker identity/lease fencing, heartbeats, health/drain/recovery and capability/resource-aware admission.
- Pluggable RuntimeProviders with CPU/GPU topologies. Native hosted Model Serving through compatible providers, including selected-GPU identity validation and a fail-closed **currently free VRAM** prestart check for VRAM-resident runtimes.
- OpenAI-compatible bounded Chat Gateway with streaming and structured tool calls; best-effort bounded admission and client-disconnect cancellation, including the known `UNKNOWN_COMMIT` outcome (see below).
- Immutable-scoped Embedding identity, and an **opt-in** same-GPU Embedding + experimental Decision/System-One runtime under a single logical Worker with `max_concurrency=1`. Decision/System-One remains `OBSERVED_ONLY`: it is uncalibrated/advisory, not autonomous authority.
- NixOS and generic-systemd + Nix installation/operation workflows on already provisioned supported Linux nodes. Existing OS, hypervisor/LXC, network, PostgreSQL service, NVIDIA driver, device exposure and model artifacts are prerequisites, not provisioned by TSUMGI.

## Supported scope and limits

| Topic | Scope / known limitation |
| --- | --- |
| OS | **x86_64 Linux** via a documented NixOS module or generic systemd + Nix Installer/TUI; pip-only is not a standalone systemd/GPU host installation. |
| Database | **PostgreSQL 17.x**, server/client **UTF8**, migrations 000–005. No automatic production schema migration or downgrade promise. |
| Security/trust | Initially intended for **trusted, private/appropriately authenticated installations and clients**. No untrusted multi-tenant native-process or shared-UID isolation guarantee. Dedicated Worker UID and stricter single-native UDS/bearer protection remain post-v0.1 work in [#149](https://github.com/upiscium/TSUMGI/issues/149). Public unauthenticated ingress is not an approved deployment. |
| Chat cancellation | A disconnected caller may encounter `UNKNOWN_COMMIT`: a Job can commit/queue or briefly run after HTTP client loss. Cancellation is **bounded best-effort**, not exactly-once, guaranteed zero-orphan, or hard-latency cancellation. Job deadline/recovery and operator inspection remain required. |
| GPU resources | TSUMGI controls logical ownership and checks currently free VRAM; measurements are **not reservations** and do not establish host-/hypervisor-wide GPU exclusion of unrelated processes. |
| Model quality | Providers and models need explicit serving bindings and profile constraints; no universal quality, correctness, context, GPU/driver compatibility, throughput or latency SLA. Default OpenCode build-agent system context can exceed a small pinned input limit; lean configured agents passed acceptance. |
| Decision/System-One | `OBSERVED_ONLY`, uncalibrated, recommendation-only; not a final decision authority. |
| Memory | [#150](https://github.com/upiscium/TSUMGI/issues/150): native Qwen3.6 host anonymous RAM grew under bounded sustained use, with no observed OOM/failed Jobs; bounded long-horizon memory plateau and 24-hour saturated-load reliability are **not proven**. |
| Deferred choices | [#151](https://github.com/upiscium/TSUMGI/issues/151) compares later Qwen and Bonsai-derived Coding models **after v0.1.0**, not a release prerequisite. SSE performance optimization remains deferred. |
| Naming | Runtime identifiers remain `astrumweaver` for backwards compatibility; full technical rename is deferred to [#120](https://github.com/upiscium/TSUMGI/issues/120). |

## Available validation / evidence boundary

- The source baseline `40e0151` is identical to the published [experimental v0.1.0-rc.1](https://github.com/upiscium/TSUMGI/releases/tag/v0.1.0-rc.1), with [exact-source unit and Nix CI SUCCESS](https://github.com/upiscium/TSUMGI/actions/runs/38657662180); earlier isolated PostgreSQL 17.11 full Python suite **1,169 PASS / 2 SKIP / 0 FAIL** and Nix Control/Worker/Installer builds passed.
- On an operator-controlled site, RC1 ran real PostgreSQL Control + five registered Workers with a pinned two-GPU Qwen3.6 model. Real OpenCode CLI 1.18.35 completed **56/56 sessions**, **12/12 scratch Coding edits**, **84/84 functional assertions**, plus an owned client SIGKILL → Job cancelled → Worker slot free → subsequent Coding edit PASS. See [#124](https://github.com/upiscium/TSUMGI/issues/124#issuecomment-6227235648).
- Sampled resident native/Worker health **144/144**, and DB registration/health **66/66** during bounded load; VRAM remained constant. The roughly 24-minute active-load run is **not** a 24-hour fully loaded stress test, latency/throughput SLA, universal GPU proof or public security audit.
- The previously demanded **documentation-only Real Smoke** ([#80](https://github.com/upiscium/TSUMGI/issues/80)) was **closed administratively by explicit maintainer decision**, not newly demonstrated as a full technical PASS. Do not invent missing installation evidence.
- **Stable-version changes require fresh exact-HEAD unit/Nix/generated-module tests and artifact checks before publication.** RC1 results do not automatically certify an unbuilt GA archive. See the GA qualification checklist for the required evidence.

## Installation, upgrading and rollback

Read [installation](../installation.md), [operator rollout/rollback gates](../operator-rollout-gates.md) and the [GA qualification checklist](../ga-qualification-v0.1.0.md).

A stable GitHub Release delivers sources, an integrity manifest, checksums and any reviewed Python wheel; it does **not** install PostgreSQL, change credentials, allocate GPUs, activate new models or replace a running Control/Worker. **Source release and named-site operator GO/NO-GO are independent decisions.** For an existing site, pin the immutable source, keep old profiles/units/credentials available, verify recoverable PostgreSQL 17 backups and restored-Control readback, and obtain [#124](https://github.com/upiscium/TSUMGI/issues/124) approval before changing services.

The GA product version `0.1.0` sorts **after** Nix RC `0.1.0pre1`. Existing pre-RC `0.1.0-dev` profiles may have a different comparison ordering; **do not use a blind Nix profile upgrade** to migrate an installation. Explicit immutable profile selection and rollback are required.

## Publication gate

Before creating the stable tag and GitHub Release, the maintainer must review the final release scope, known risks, exact-commit tests, immutable artifacts and SHA-256 checksums, then provide **explicit approval for v0.1.0 publication** under [GA qualification](../ga-qualification-v0.1.0.md). The fact that this document exists **does not grant publication authority**, nor does it imply PyPI/signing/third-party distribution approval. Verify the actual publication separately.
