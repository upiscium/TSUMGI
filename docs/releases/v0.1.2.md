# TSUMGI v0.1.2 — Maintenance GA Scope and Qualification

> This source note does not establish publication and does not authorize an automatic Control/Worker upgrade. The exact stable tag and public RELEASE-MANIFEST.txt, not a moving branch, establish release identity and artifact integrity.

| Surface | GA |

This wraps up **three** reviewed changes since v0.1.1 GA, without a new feature set:

- **PR #158:** Pinned upstream Qwen3.8 CUDA/driver/PTX Native backend as an opt-in distinct Nix package. Default upstream and optional Bonsai packages are unchanged; no universal hardware guarantee.
- **PR #166:** Explicit authenticated reconciliation after Control-marked heartbeat TTL Worker Offline, preserving GPU ownership/fencing, durable Job lease, Serving identity and operator Offline/Draining fail-closed policy.
- **PR #169:** Strict Chat Gateway `store: false` compatibility with OpenCode v2, stripping the field before durable Job compilation; `store: true` remains unsupported, invalid types rejected, v1 backward/Tool stream maintained.

The full Qwen3.8 dual RTX3060/Control/OpenCode/rollback acceptance, Control/vega Worker reconnection, and v1/v2 OpenCode + Bonsai compatibility were physically observed (#157, #162, #167). They are **bounded operational evidence**, not blanket hardware, model-quality or uptime warranties.

## GA qualification / maintenance handoff

1. Confirm RC public source/tag and SHA256SUMS; GA functional source and six SQL migrations must remain identical to the RC. GA changes only Python/Nix product versions, release-facing tests/docs and README.
2. Independently review GA changes; require complete exact-commit Python regression, source CI unit/nix, generated NixOS checks and Nix Control/Worker/Installer/integration plus Qwen3.8/Bonsai package qualification.
3. Build wheel, sdist, deterministic Git archive twice from the exact GA source; prove byte identity, module and migration integrity, hashes and annotated Git tag. Publish as stable GitHub Release with RELEASE-MANIFEST.txt and SHA256SUMS, without claiming independent cryptographic signing.
4. Preserve existing installed Nix profiles; publication **does not** upgrade running Control/Worker, GPU models or PostgreSQL. Any future deployment requires a separately authorized rollback plan.
5. After verified public RC and GA, close release tracking #170 and enter **maintenance phase**: bounded fixes, operational health and security follow-ups only until new features are prioritized.

## Deferred features / limitations

- PostgreSQL 17 UTF8 migrations `000`–`005` unchanged. Trusted/private LXC Native loopback/same-UID isolation remains insufficient for hostile multitenancy; #149/draft PR #148 held.
- Bonsai 2 PQ2_0 is optional and has bounded Coding correctness limitations; weights/NVIDIA driver libraries not redistributed.
- #160 continues as monitoring; #120 is deferred technical rename.
- **Stored Completions #168 stays Future Work.** `store: false` does not suppress ordinary PostgreSQL operational Job/event retention, while `store: true` is unsupported.
- No PyPI, Nix binary cache, signed artifact attestation, automatic production rollout, general client/GPU correctness or long-term SLA is implied.
