## Stable and experimental scope

1. **OpenCode Chat interoperability ([#209](https://github.com/upiscium/TSUMGI/issues/209)).**
   Strict reviewed `reasoning_effort` values `low/medium/high` are
   accepted as documented **no-effect compatibility hints** (not
   operative model reasoning control). Ordered bounded text-part user
   content is concatenated without changing messages, tool history,
   streaming, request bytes, or existing `store:false` semantics.
   Invalid media, fields, size, `store:true` and mismatched tool IDs
   still fail closed. Actual production Qwen3.8-27B/Bonsai2-27B
   OpenCode 1.18.35 plain and read-Tool round trips **4/4 PASS**,
   strict negative HTTP checks **9/9 PASS**, with the original stable
   Gateway restored under a reversible Nix Control profile.
2. **Opt-in bounded audio groundwork ([#174](https://github.com/upiscium/TSUMGI/issues/174),
   [#175](https://github.com/upiscium/TSUMGI/issues/175),
   [#180](https://github.com/upiscium/TSUMGI/issues/180)).**
   Job-scoped WAV artifacts, providerless HTTP speech/transcription
   ingress, immutable voice catalog and separately opt-in Control/Worker
   managed audio serving integration. These are **source-level contracts**
   and packaging capabilities, not evidence of a deployed audio engine.
3. **Audio managed-only admission enforcement
   ([#214](https://github.com/upiscium/TSUMGI/issues/214) / PR #217).**
   Workers advertising `audio.synthesize`/`audio.transcribe`
   reject a bare generic `executor.factory` before host/GPU/network
   effects and require an explicitly reviewed `runtime.manifest`,
   provider-bound readiness and coherent `RuntimeHealthState.READY`
   before audio registration. Non-audio factories and Chat remain
   supported. This is a **fail-closed safety gate, not successful
   VOICEVOX/Style-Bert/Japanese STT inference readiness**.
4. **VOICEVOX and Style-Bert-VITS2 adapter source contracts (#176/#177).**
   Source support exists, but no default model runtime is enabled.
   Actual owned process/socket readiness, speaker/model license and
   pinned-byte qualifications, Nix/Worker registry integration,
   Japanese STT selection and live audio quality/security E2E remain
   future operational work (#215/#216/#178/#179/#181). Their absence
   cannot be interpreted as completed runtime support.

The maintainer explicitly requested a patch-number increment. This
release also contains **opt-in functionality**, so it is not described
as a fixes-only semantic-versioning change. The stable core remains
the already supported Control/scheduler/Chat/Worker substrate; audio
functional serving is outside the GA guarantee until separately
qualified and explicitly enabled.

## Operational boundaries

- PostgreSQL 17 migration files `000`–`005` are unchanged since
  v0.1.2. No release-time migration.
- Existing `v0.1.2` runtime artifacts and optionally installed
  Qwen/Bonsai GPU backends are not silently replaced.
- A public GitHub Release does **not** upgrade running Control/Worker,
  alter existing credentials, start model downloads, or change GPU
  passthrough/ownership. Site rollout must use explicit operator
  GO with old-profile rollback evidence.
- `store:false` has no effect on ordinary durable Job/event retention;
  Stored Completions (#168) remains unimplemented.
- The TSUMGI technical identifier rename (#120), hardened same-UID
  isolation (#149), long-running performance guarantees and broad
  host/GPU compatibility are not part of this GA.
- Forcing the OpenAI-targeted global `plan` Agent to a smaller TSUMGI
  model may exceed context limits (dotnix #68); dedicated configured
  local agents were qualified separately.
- No PyPI publication, binary cache, signed source provenance,
  universal voice/model quality or GPU CUDA compatibility is implied.
