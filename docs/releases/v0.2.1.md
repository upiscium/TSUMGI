## Change since v0.2.0

**Control pools its PostgreSQL connections (PR #277).**

- **Before:** Control opened a new connection for every repository call. In
  the operator's production that costs 40–54 ms, against 1.2 ms on a reused
  connection. Every Worker claim poll, event publish, heartbeat and Gateway
  stream poll paid it.
- **Now:** calls without an admission deadline borrow from a
  `psycopg_pool.ConnectionPool`.
  - Settings: `[control]` keys `db_pool_min_size` (default 1),
    `db_pool_max_size` (10) and `db_pool_timeout_seconds` (2).
  - The pool hands out only checked live connections, and replaces a
    connection that the server or network dropped.
  - Each checkout still runs the UTF8 check. A connection is rolled back
    before it returns, and one that fails its checks is closed.
- **Unchanged:** bounded chat admissions still open a fresh connection with
  their own connect, statement and lock timeouts.
- **Unreachable database:** the 2 s wait keeps it a fast
  `StorageUnavailable`.
- **Dependency:** `psycopg-pool` is new. It is in the `postgres` extra and in
  the Control and Installer Nix environments. Without it, Control falls back
  to one connection per call.
- **Behaviour change:** `ALTER ROLE/DATABASE ... SET` now reaches pooled
  connections only as they are replaced, at most one hour later. Restart
  Control to apply such a change at once.

No Worker, Gateway API, protocol or schema change. PostgreSQL migrations
`000`–`005` are unchanged since v0.1.3.

## Production evidence (operator site, 2026-11-17)

Control ran the functional source above. At the same time, sirius's Worker
claim poll interval went from the 1.0 s default to 0.1 s. That is site
configuration, not part of this release.

Five-token streaming requests through the public endpoint, five runs each:

| Profile | v0.2.0 | v0.2.1 Control (+ sirius poll 0.1 s) |
| --- | --- | --- |
| `qwen3.6-35b-a3b-fast` (sirius) | 1.7–2.0 s | 0.51–0.63 s |
| `qwen3.6-35b-a3b-short` (deneb) | 0.9–1.3 s | 0.46–0.63 s |
| `qwen3.6-35b-a3b` (spica) | 1.2–1.6 s | 0.83–1.08 s |

A 300-token stream on the fast profile went from 5.4 s to 3.8 s. No Control
or Worker errors were logged after the rollout.

## Operational boundaries

- Publishing the tag or the GitHub Release does not update running services.
  Only Control needs the new build for this change. Site rollout still needs
  an explicit operator GO with a rollback path.
- Not part of this release:
  - llama.cpp bounded shutdown and cgroup containment (#237, #240);
  - a push or long-poll Worker claim;
  - the audio epic (#173). **No audio engine is qualified or enabled by
    default.**
- No PyPI publication, binary cache or signed provenance is implied.

## Publication gates

- The exact release source passes Python and Nix CI.
- Wheel, sdist and Git archive are built twice and compared. Metadata,
  migrations and archives are inspected.
- The annotated `v0.2.1` tag is published with `RELEASE-MANIFEST.txt` and
  `SHA256SUMS`, and the asset hashes are read back. It is published as stable
  ("Latest").
