## Breaking change

The Bonsai 2 llama.cpp runtime is removed (#265).

- **Effect:** a stored Setup or runtime manifest that names
  `runtime_flavor: "bonsai2-pq2"` no longer loads. It fails with
  `unsupported llama.cpp runtime_flavor`.
- **What to do:** remove or migrate such manifests before upgrading.
- **Why the minor version:** in the 0.x series an incompatibility is
  signalled by the minor version, so this release is `0.2.0`.

## Stable scope since v0.1.3

1. **Strata runtime provider (#266, #267).**
   - Serves Qwen3.6-35B-A3B on a single GTX 1080 Ti (64K) and at 12K.
   - Schema-declared booleans in tool arguments are restored.
   - The Worker refuses a contract whose `total_tokens` differs from the
     Strata run context.
2. **FreeToken chat backend for sm_61 (#261, #263, #264).**
   - Pinned installer, Gateway chat in a real Worker, and Worker permissions
     for production.
   - It is kept as an alternative runtime. Follow-ups #262 items 1–3 are
     open.
3. **llama.cpp KV cache element types (#268).**
   - `cache_type_k` and `cache_type_v`, for example `q8_0` for 192K on two
     RTX 3060s.
4. **SSE keep-alive (#269).**
   - `: keep-alive` comments while a stream waits for its first chunk.
5. **Serving contracts checked against runtime context at Worker startup (#270).**
6. **OpenCode-ready streaming (#272, #273, #274).**
   - **Worker chunk coalescing (#272):** streams arrive at decode speed
     instead of about 10 tokens/s.
   - **HTTP errors for pre-stream failures (#273):** a failure before the
     first frame returns a normal HTTP error, so OpenCode compacts on context
     overflow.
   - **Bounded admission wait (#274):** the optional
     `admission_wait_seconds` waits for a busy single replica instead of an
     instant 429. Overload 429s carry `Retry-After`.

Source-only work stays outside the GA guarantee:

- External VOICEVOX groundwork (#247) and the audio provider reviews.
  **No audio engine is qualified or enabled by default.**

## Qualification evidence (operator site)

The RC2 source (main `92f023d`, functionally identical to the tag) runs on
the maintainer's production site since 2026-11-17. Control uses
`admission_wait_seconds = 120`.

| Host | Profile | Runtime |
| --- | --- | --- |
| sirius | `qwen3.6-35b-a3b-fast`, 196608 | llama.cpp b11430, KV `q8_0`, 2x RTX 3060 |
| spica | `qwen3.6-35b-a3b`, 64K | Strata 0.2.13.1, GTX 1080 Ti |
| deneb | `qwen3.6-35b-a3b-short`, 12K | Strata 0.2.13.1 |

**Streamed delivery of 300 tokens** through the public endpoint:

| Profile | rc.1 | RC2 |
| --- | --- | --- |
| 192K | 31.8 s | 5.4 s |
| 12K | 29.6 s | 15.0 s |
| 64K | — | 17.3 s |

**OpenCode 1.18.35 runs against production**, using the real dotnix provider
and agent configuration:

- **192K:** passed every round:
  - code lookup with file and line;
  - a follow-up turn in the same session;
  - a 44K-token multi-file question;
  - delegation to a hidden subagent;
  - a 2048-token answer in 29 s;
  - three concurrent sessions;
  - a two-bug fix with the edit tool.
- **64K:** passed lookup, follow-up, long-file question, the edit fix and
  concurrent sessions.
- **12K:** lookup and follow-up passed. The edit task fixed one of the two
  bugs, which is a model limit.
- **Logs:** no Control or Worker errors after the RC2 rollout, other than
  intended context-overflow rejections.
- **Context overflow:** now reaches OpenCode as HTTP 400, and OpenCode
  compacts.
- **Remaining limit on 12K:** when a single file read does not fit, the model
  can re-read the whole file after each compaction and loop. Each rejection is
  correct, but the session does not finish. The 12K profile is not suited to
  file-reading agent work.

This evidence covers the maintainer's site only. It is not a universal
hardware or model qualification.

## Operational boundaries

- PostgreSQL 17 migrations `000`–`005` are unchanged since v0.1.3. No
  migration runs at release time.
- `admission_wait_seconds` is off (`0`) unless configured. Keep
  `admission_wait_seconds + stream_keepalive_seconds` below the read timeout
  of any proxy in front of the Gateway.
- A 12K profile cannot fit a single tool result larger than its window, even
  after compaction. With OpenCode it can loop between re-reading and
  compacting. Route file-reading agent work to a larger profile.
- Publishing the tag or the GitHub Release does not update running services,
  credentials, model downloads or GPU ownership. Site rollout still needs an
  explicit operator GO with a rollback path.
- Not part of this GA:
  - llama.cpp bounded shutdown and cgroup containment (#237, #240);
  - the VOICEVOX operator preview (#260) and the audio epic (#173);
  - Control PostgreSQL connection pooling;
  - #120, #149, #168, #197.
- No PyPI publication, binary cache, signed provenance, or universal model or
  GPU compatibility is implied.

## GA publication gates

- The published RC2 tag and its assets are verified against `SHA256SUMS`, and
  the RC2 functional source is frozen.
- The exact GA source passes Python and Nix CI, with the merged-source CI
  green.
- Wheel, sdist and Git archive are built twice from the exact GA source and
  compared. Metadata, migrations and archives are inspected.
- The annotated stable `v0.2.0` tag is published with `RELEASE-MANIFEST.txt`
  and `SHA256SUMS`, and the GitHub asset hashes are read back.
- It is published as **stable GA** ("Latest"), not as a prerelease. Nothing is
  deployed automatically.
