# TSUMGI v0.4.0-rc.1 — Audio Epoch Release Candidate

> **Pre-release candidate, not stable GA.** This note describes the proposed
> prerelease scope. The release is published only once the annotated Git tag
> and the GitHub Release assets (`RELEASE-MANIFEST.txt`, `SHA256SUMS`) are
> verified. A public prerelease does **not** upgrade any installed Control,
> Worker, GPU runtime, PostgreSQL schema or site configuration.

## Version identity

| Surface | Intended identity |
| --- | --- |
| Git tag | `v0.4.0-rc.1` — annotated prerelease |
| Python distribution | `tsumgi==0.4.0rc1` |
| Nix Control, Worker, Installer and integration packages | `0.4.0pre1` (sorts before `0.4.0` GA) |
| Prior stable | Published `v0.3.0` |
| Candidate functional baseline | `main` after PR #311 |
| Tagged identity and checksums | The release manifest and `SHA256SUMS` of the exact tag establish the published source and artifacts |

## Why the minor version changes

This candidate adds an operator API and a PostgreSQL migration (`008`) on top of
`v0.3.0`. In the 0.x series new surface that needs a schema step is signalled by
the minor version. Nothing is renamed or removed: the names, paths and API fields
of `v0.3.0` are unchanged.

## Changes since v0.3.0

1. **Release and expiry for audio epoch preparations (PR #305).** The guard that
   keeps a Worker out of registration, heartbeat, claims, state changes and job
   selection is now "has an *active* preparation" instead of "has any
   preparation". A preparation is active while it has no release record, has not
   expired, and its qualification is not revoked. Adds the operator-only
   `POST` and `GET /v1/admin/audio-epochs/{worker_id}/{epoch}/release` routes
   (same credential and strictness as the fence routes). History is never
   rewritten. The audio feature stays default-off.
2. **PostgreSQL migration `008_audio_epoch_preparation_releases.sql`.** Additive
   and append-only (`ON DELETE RESTRICT`). Control refuses a database whose
   applied migrations do not match the packaged set, so **apply `008` before
   starting this Control** (see [Control plane](../control-plane.md)). Rolling
   back to `v0.3.0` Control needs no schema change: the table is simply unused.
3. **VOICEVOX process identity check (PR #306 line of work).** The owned-process
   check tolerates the engine bootloader's re-exec window instead of failing
   during it.
4. **Operator console look (PR #311).** Dark theme with an Evangelion-style
   warning-panel design over a starfield. Displayed content is unchanged, and the
   footer line "認証なしの管理画面です。内部ネットワークからのみ到達できるようにしてください。"
   is removed. **The console still has no authentication unless configured;
   removing the line does not change that.** Keep it reachable only from the
   internal network. The page uses only same-origin CSS, so the strict CSP is
   unchanged.
5. **Documentation (PRs #304, #306, #307).** The docs are published on GitHub
   Pages, the install pages are refreshed for `v0.3.0`, and there are two
   evidence documents: Japanese speech-to-text measurements (#178) and real-engine
   runs of VOICEVOX and Style-Bert-VITS2 (#215, #216, #247).

## What this candidate does not claim

- **No audio engine is qualified.** The evidence documents are inputs to the
  maintainer's decision, not a qualification. They were produced on one
  developer machine, not on the production hosts, and must be repeated there.
- Epoch preparation can now be released, but there is no activation path yet;
  the proposal is in the design notes and is not part of this release.
- The new console styling has been checked in a browser with sample data only,
  at desktop width. Mobile width, the model-check tab and the first-setup page
  were not looked at.
- This release does not update any running service. Installing it on a host is
  a separate, deliberate step.
