## What this candidate includes

TSUMGI is a capability-oriented compute fabric with a PostgreSQL-backed Control plane, registered Worker execution, lease/recovery and resource-aware scheduling. Its code supports several runtime providers and separately provisioned CPU/GPU Worker nodes; TSUMGI does **not** provision operating systems, containers, hypervisors, passthrough or NVIDIA drivers.

- **Chat API and client lifecycle:** OpenAI-compatible chat serving with streaming and tools, reviewed persistent Job identities and bounded best-effort client-disconnect cancellation. [#110](https://github.com/upiscium/TSUMGI/issues/110) was completed with historical real OpenCode **1.18.35** → PostgreSQL Control → CUDA Worker inference cancellation **6/6 PASS** on a disposable GPU fixture (before/after first streaming chunk).
- **Bounded admission cancellation ([#137](https://github.com/upiscium/TSUMGI/issues/137)):** merged via [#145](https://github.com/upiscium/TSUMGI/pull/145). Caps concurrent ingress, admissions and post-admission cancellation attempts; bounds admission database transactions on supported PostgreSQL 17, performs exact-key readback/reconciliation and avoids unnecessary cancellation of successful SSE responses.
- **GPU responsibility boundary:** logical Worker/GPU identity and selected-device checking, fail-closed startup when conservative **currently free VRAM** is insufficient for a pinned resident runtime. Free-VRAM sampling is not a reservation, and TSUMGI does not enforce Proxmox/host-wide GPU exclusivity over unrelated processes.
- **Embedding + System-One coexistence:** opt-in pinned managed models may share one logical Worker GPU resource with conservative memory/admission checks and `max_concurrency=1`, subject to exact runtime/provider compatibility.
- **Installation:** supported target architecture is `x86_64-linux` with a documented NixOS module or generic Linux systemd + Nix installer/TUI workflow. Python/pip alone is **not** a complete host deployment.

## Supported prerequisites and experimental boundary

| Surface | RC support / exclusion |
| --- | --- |
| Control database | **PostgreSQL 17.x**, with server and client `UTF8` encoding; migrations 000–005. This RC does not install PostgreSQL, convert an incompatible database or authorize a live schema migration. |
| CPU/GPU host | Pre-existing supported Linux node and functional drivers where GPU-backed. Model availability, capabilities and GPU device exposure are host prerequisites. |
| Chat | Source and protocol behavior tested in bounded scenarios, not an inference-quality/throughput/latency SLA or assurance against all cancellation races. |
| Cancellation uncertainty | **UNKNOWN_COMMIT** means that even after an empty primary readback a *later* committed Job may become QUEUED or briefly execute without its client. Gateway crash/DB blackhole can also leave unresolved work until ordinary Job deadline/Worker recovery; **no zero-orphan or exactly-once client-retry promise**. |
| Embedding | Serving is bound to a pinned embedding-space identity; arbitrary vectors/spaces are not interchangeable. |
| Decision/System-One | **OBSERVED_ONLY**, uncalibrated, advisory/recommendation-only; not an autonomous decision authority. |
| Dual resident GPU Worker | Source and isolated runtime evidence available; **site activation not granted**, see #124. |
| Branding | `astrumweaver` stable technical identifiers retained for backward compatibility; the full rename is still open under [#120](https://github.com/upiscium/TSUMGI/issues/120). |

No claim is made for universal provider/model quality, all possible GPUs, untested operating systems or production failure-recovery objectives. The previously observed native-GPU SIGKILL **6/6 PASS** was from [#134](https://github.com/upiscium/TSUMGI/pull/134), **not a new GPU replay on this exact RC source**.

## Upgrade and safety

This prerelease does **not** upgrade any installed Control, Worker, PostgreSQL schema or GPU service. Do not run rolling upgrades against running services merely because an RC branch or tag exists. **Nix version caveat:** this candidate uses `0.1.0pre1` rather than `0.1.0-rc.1` in Nix derivations so it sorts before final `0.1.0`; earlier `0.1.0-dev` can sort newer than it, so do not rely on implicit profile upgrade selection. Pin the exact approved source when migrating a site.

- Review [installation guidance](../installation.md), [release readiness](../release-readiness.md) and [operator rollback gates](../operator-rollout-gates.md).
- Existing sites require named owners, immutable old/new executable paths, separate **recoverable PostgreSQL backup and restored-Control verification**, known schema compatibility, isolated old→new→old rehearsal, role-secret/UDS boundary checks and a separate explicit **#124 site GO/NO-GO**.
- This first RC is scoped to trusted clients and explicitly configured ingress/auth boundaries; it is **not** a claim of production tenancy isolation or hard infrastructure GPU isolation.
