This candidate is an intentionally narrow **Bonsai 2 27B PQ2_0 opt-in backend release**; the default upstream `llama-cpp` runtime and existing v0.1.0 Worker installations are not replaced automatically. It includes the merged source improvements already present in the RC but does **not** include unmerged upstream-Qwen3.8 packaging [#158](https://github.com/upiscium/TSUMGI/pull/158) or optional native UDS/bearer [#148](https://github.com/upiscium/TSUMGI/pull/148).

## Official supported Bonsai Runtime

- Qualified model only: [PrismML Ternary-Bonsai-2-27B-PQ2_0](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf), revision `b072e1d3b35a0a630cece372c2127528e0994386`, file `Ternary-Bonsai-2-27B-PQ2_0.gguf` (7,206,168,928 bytes), full SHA-256 `3907dc1658db1f78a9826bf8d5bcb8dc65db0d466388937af57f2294fae62ec1`.
- Opt-in `runtime_flavor=bonsai2-pq2`, distinct from the default upstream `llama-cpp`; the PrismML fork is pinned to native source `e8fd209c975c80aa7fb36a8423571ff3b1b7e955` with a Nix fixed-output binary SHA-256.
- Review scope: **one GPU per Worker**, VRAM-only native serving, Conservative VRAM admission/fail-closed, model hash verified before launching the owned Native child, Context at least 8,192, Jinja structured Tool Calls, `--reasoning off` and reviewed Flash Attention flags.
- Explicit host `libcuda.so.1`, PTX JIT and NVVM library support is required on GTX1080Ti Pascal; matching NVIDIA driver libraries remain operator-supplied. No proprietary NVIDIA driver libraries or model weights are bundled with the RC or GA source archive.
- The Nix runtime profile for Bonsai is independent of the upstream Nix `runtime-llama-cpp` profile. Use a fixed reviewed Installer source, separate profiles and rollback to avoid in-place mutation of an immutable old installation.

## Database and wire compatibility

PostgreSQL 17 remains the supported database. Migration source files **000–005 are unchanged** relative to published [v0.1.0 GA](https://github.com/upiscium/TSUMGI/releases/tag/v0.1.0); this GA candidate has no additional schema migration. The underlying durable Worker GPU ownership/fencing, identity, bounded admission, Chat/Embedding/Decision gateways and narrow configured capabilities retain their previous contracts.

**Do not convert an Offline Worker to Online by a generic heartbeat.** A transient Control acknowledgement loss can leave the Worker safely Offline despite successful new heartbeats; this availability limitation is tracked by [#162](https://github.com/upiscium/TSUMGI/issues/162). Until a reviewed reconnection fix is available, the accepted recovery is an explicit, authorized re-registration of an idle Worker after verifying no conflicting GPU owner, runtime readiness and leases. Automation that silently overrides GPU ownership remains out of scope.

5. **Explicit operator acceptance** for `v0.1.1` GA publication and separately for any live fleet/profile updates. The previous `v0.1.0` GA recovery profile remains available until accepted.

## Safety and known limitations

| Area | Boundaries that remain in GA |
| --- | --- |
| Trust model | Trusted/private LXC and selected GPU only. A compromised Native child running with the Worker's UID is not isolated from the Worker’s secrets; [#149](https://github.com/upiscium/TSUMGI/issues/149) stays deferred. |
| GPU | Logical lease/owner exclusion and free-VRAM checks do not reserve memory against unrelated host processes or other hypervisor tenants. |
| Memory and saturation | No 24-hour saturated-load memory plateau, universal throughput or latency SLA; see [#150](https://github.com/upiscium/TSUMGI/issues/150). |
| Cancellation | A disconnected HTTP caller can leave an UNKNOWN_COMMIT or short-lived durable Job; cancellation is bounded best-effort, not globally exactly-once. |
| Model guarantees | Only Bonsai 2 27B PQ2_0, initial GTX1080Ti 11GB qualification; no universal PrismML/PQ format, other GPU, model accuracy or 32k-context service guarantee. |
| Embedding/Decision | Decision/System-One is uncalibrated, `OBSERVED_ONLY`, advisory; not independent autonomous authority. |
| Release distribution | Publishing a source tag and GitHub Release does not provision drivers, install models, migrate Postgres, upload PyPI, sign software or update deployed Workers. |

## Install and rollback

Keep an independent Nix profile for each immutable tag/commit. Locked flake references are intentionally **not** eligible for blind `nix profile upgrade --all`; instead, install an explicit reviewed candidate into a separate profile and switch only a single authorized site. Preserve the existing GA and currently working Worker profiles/units and a PostgreSQL backup.

See [Bonsai Runtime details](../bonsai-llama-cpp.md), [Operator rollout/rollback gates](../operator-rollout-gates.md) and [#164 GA promotion](https://github.com/upiscium/TSUMGI/issues/164). The GitHub Releases page—not this proposal—is authoritative for any eventual public `v0.1.1` release.
