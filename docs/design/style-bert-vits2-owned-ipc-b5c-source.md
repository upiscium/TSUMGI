# TSUMGI #216 B5c — isolated Style-Bert-VITS2 process and bounded IPC (R1)

**Status: source-only / synthetic-process qualification.** This change does not ship a Style-Bert-VITS2 model, upstream native TTSModel.infer, runtime installer, generic provider registry binding, NixOS/systemd service or production-ready integration. It is not evidence of correct Japanese speech output, GPU consumption, legal voice rights or a secure subprocess sandbox.

## Scope and contracts

- Provider-local style_bert_vits2_managed.py implements a ManagedRuntime bound to exactly one operator-selected StyleBertVits2ProviderConfig and ServingDeploymentDeclaration. The deployment runtime/adapter/model pins must match the exact binary/runner/weight byte hashes and the contract must match audio.synthesize, openai-audio-speech-v1, the pinned semantic revision and ja/wav. A forged serving declaration or presence of a runtime.manifest does not create authority by itself.
- Pinned source artifacts are the one selected .safetensors/.onnx, config.json, style_vectors.npy, fixed runner script and interpreter binary. All exact absolute paths are individually SHA-256 checked before subprocess start; symlinks, missing files, duplicate weight files, mismatched bytes and invalid model filename are rejected. Read-only file stat identities are rechecked on each runtime health call to catch basic post-boot artifact replacement. This does not prove that the future native runner actually loaded the attested bytes or close kernel-level TOCTOU and process identity gaps.
- Device intent is strictly CPU or one explicitly Worker-owned GPU UUID. Declared host RAM and GPU VRAM floors must fit existing WorkerSpec / RuntimeHostFacts. These are configuration checks, not measured GPU/host acceptance; no GPU scheduler changes or device provisioning.
- voice_rights_qualified=True and rights_review_sha256 represent *operator-declared* approval only. These fields are not a legal review of the specific voice/model's license; that remains an operations gate.

## Owned process and IPC

- One child per ManagedRuntime instance, launched with fixed argv (pinned interpreter -I -u pinned runner script), a private stdin/stdout pipe, stderr discarded, a fresh isolated POSIX process group, minimal fixed environment, and no text/model path in shell arguments. Model artifact paths are included only in bounded private bootstrap IPC frames, never log/argv/Job JSON. There is no connection to an unowned model server.
- IPC is a 4-byte network-order length followed by UTF-8 JSON control frames with a 32 KiB cap, exact protocol version, request ID and runtime UUID epoch bound to the ServingDeploymentDeclaration. Duplicate JSON keys, wrong epochs, stale request IDs, unreasonable lengths or malformed JSON fail closed. Audio follows the response header as bounded raw WAV bytes (max_output_bytes checked before reading), avoiding base64/durable Job JSON. Existing Style-Bert audio executor enforces the canonical PCM16 WAV and finite duration contract before a single media stage.
- Bootstrap requires the child to report exact pinned model hashes, speaker/style list, worker/deployment/device and a completed probe. The test child echoes synthetic assertions. It does not load actual weights, perform a native readiness probe, or prove that a malicious child honestly reported the model. A future real runner requires separate source/security qualification and host acceptance.
- Native synchronous infer must run solely inside the child. synthesize() awaits IPC asynchronously; one inference at a time per child, no hidden queue. Worker heartbeat/supervisor coroutines are not blocked by native infer. On timeout, cancellation, malformed IPC or child death, the owned runtime latches FAILED, attempts process-group terminate/kill and reaps the direct child before returning. stop() revokes admission before any await, cancels in-flight executor jobs, serializes process cleanup and bounds task draining. Previously cached executors reject jobs after stop; a generation-bound media wrapper denies late staging receipts if cancellation was suppressed. An uncertain upload is not rolled back. No alternate automatic claim, replay, or automatic process restart. Return bytes are not published from failed/stale attempts.
- Health reports READY only after bootstrap and while the same known POSIX process group and on-disk identities still appear unchanged. An unexpected exit or file drift latches FAILED. The existing RuntimeHealthSupervisor is still the Worker admission authority, not this process self-report. SIGTERM/SIGKILL of an isolated process group is not a cgroup, PIDFD, security sandbox or proof of cleanup for forked descendants that escape the group. Production must review descendant cleanup and PID-reuse risks separately.
- Source-only ManagedRuntime is not in the shared RuntimeProvider registry and cannot be selected by existing Worker manifests until an independently reviewed #180 integration slice. The base Style-Bert executor remains unqualified by itself, in keeping with merged #214.
