## Bounded operational sequence — separate operator maintenance approval required

1. **Fresh preflight (read-only):** verify exact current service identities, hashes of 8K Worker/Control snapshots and pinned original Nix closure; inspect every active Worker and current Control registry, zero queued/running/claimed/nonterminal Qwen Jobs, no active request/stream; sample both GPU UUIDs/VRAM and record source heads. Block new admissions for the maintenance window through a separately qualified means. A one-time zero-job snapshot is not an admission freeze.
2. **Protected rollback:** preserve both host backups and the original 8K Nix root. Have an independently approved site-local recovery procedure that can restore old Worker+Control catalogs together. The previous R8 10-minute rollback timer was for that test ONLY and is not armed now. Do not assume a timer will prevent GPU overlap; a timer that races the new Native is dangerous.
3. **Stage only reviewed candidate inputs privately:** new 12K Runtime manifest and Serving manifest on Sirius, full Qwen+Bonsai Control Catalog on Control; verify parser acceptance, immutably new execution/evidence digest provenance and matching revisions. Keep filenames marked REVIEW_ONLY until signed off. Never install synthetic/PENDING hashes as a real declaration.
4. **Stop old 8K Worker intentionally:** while old source remains backed up and no Jobs are active, stop the exact `astrumweaver-worker.service`. Its current `TimeoutStopSec=90s` has previously exhausted during R8, leaving native llama-server until systemd killed it. Failure/timeout means **BLOCKED**. Verify the original Worker/native wrapper and ALL known descendants have exited, original systemd cgroup is empty or removed with no unexpected process, and no Qwen GPU process retains the two reserved devices. Use the exact known Worker cgroup + native process ancestry, local `fuser` and /proc GPU device FDs, and NVML GPU UUID + compute process count/memory before and after stop. Because NVML and LXC PIDs differ, **do not compare raw PIDs across sources**. Require both target GPUs to have no residual compute processes, and no local GPU device holder attributable to the retired run; any unmatched residency or cgroup/identity uncertainty blocks the cutover. Do not rely on a one-shot `ps` or `nvidia-smi` alone. Never start a new 12K model while the old one might still exist. No global `pkill`, GPU reset, arbitrary PID/group kill, or other workers touched. If ambiguous, stay 8K/recovery only.
5. **Start 12K Worker alone:** install only the reviewed 12K Runtime/Serving manifests for the same pinned model and binary, then start Sirius Worker at 12K. Verify /ready HTTP 200, native /slots `n_ctx=12288`, correct new Deployment/Serving revisions and fresh Worker epoch. During fresh uncached 10K prefill, sample each GPU's minimum free VRAM; require >=2048 MiB throughout observed peak, no OOM or CUDA faults. Independently check input token accounting and bounded Chat/Tool/Streaming + cancellation; no overlapping model process.
6. **Promote shared Control/Gateway:** after 12K Worker qualification and exclusive ownership, atomically replace the complete Control Chat Catalog with the reviewed Qwen 12K profile (unchanged Bonsai), then **restart the shared Control service** within the approved brief outage. Verify Control health/ready, registered matching 12K Worker epoch and Deployment/Contract, `/v1/models`, Chat/Tools/Stream, malformed request 400, over-limit 400, oversized-body 413 and zero misbound Jobs **under the existing `client_auth=none` policy**. In this current configuration unauthenticated models 200 is expected, not an auth failure; an unauthorized 401 test applies only to a separately configured bearer-policy deployment. Do not change Control auth mode during 12K cutover. This is a scheduled site-impacting action affecting other Gateway users. Require rollback and post-restart Bonsai health confirmation.
7. **Client only after Gateway Ready:** change only Adam's TSUMGI Qwen OpenCode `limit.context` from 8192 to 12288, keep output 2048 and Bonsai untouched, and prove the real 7841-token plan override plus dedicated Agent chat/Tool roundtrips without altering the user's global OpenAI plan model. If client config is Nix-managed, update the tracked source rather than a drifting generated file.
8. **Failure/rollback:** stop admission immediately; ensure new 12K Native is fully gone before old 8K start. Restore original 8K Sirius Runtime/Serving/Worker and Control complete Catalog/Unit/env from verified protected snapshots in reverse order, restart original Worker+Control only when no opposing Native exists, then restore OpenCode 8192. Require old 8K slot/Worker/Control ready, Bon​sai unchanged, and no duplicated active GPU ownership. Uncertain process/identity/Manager ACK means STOP and manual recovery, not automatic release or silent fallback.

## Explicit release decision

The above gives a narrower **operational** 12K path without completing generic #240 R5c first. However, it does not mathematically solve the known process-group reuse/non-atomic descendant enumeration concerns from #237; neither a single `populated=0` observation nor absence in `/proc` is an independent GPU-release receipt. A documented maintenance-window risk decision and independently reviewed service operation are still necessary before a real cutover.

**No live unit stop/restart, manifest change, Control DB mutation, GPU reset, provider-client change, Ready/Merge or 12K activation occurred in R14.** Maintain original 8K service until authorized and reviewed source/evidence/rollback preconditions pass.
